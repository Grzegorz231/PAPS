# Лабораторная работа №2
Тема: Использование нотации C4 model для проектирования архитектуры программной системы  
Цель работы: Получить опыт использования графической нотации для фиксации архитектурных решений.

## Диаграмма системного контекста

Диаграмма системного контекста отражает границы проектируемой системы и её взаимодействие с внешними участниками.

### Основные элементы диаграммы

* Пользователь - отправляет исходный запрос и получает уточнённый результат;
* Эксперт предметной области - наполняет и актуализирует онтологию и правила предметной области;
* ИИ-ассистент обогащения запросов - анализирует запрос, использует онтологию и формирует корректную формулировку;
* Специалист - получает итоговый обогащённый запрос.

## Диаграмма контейнеров

Диаграмма контейнеров демонстрирует архитектуру уровня приложений, их обязанности и сетевое взаимодействие.

### Выбор архитектурного стиля

В качестве базового архитектурного стиля выбрана сервис-ориентированная архитектура.

Причины выбора:
* разделение ответственности между UI, ИИ-обработкой и доступом к онтологии;
* независимое развитие и масштабирование модулей;
* упрощение интеграции новых моделей и источников знаний;
* поддержка распределённого развертывания и сетевого взаимодействия.

### Основные элементы диаграммы

* Веб-клиент - интерфейс пользователя для ввода запроса и отображения результата;
* Сервер приложений - принимает запросы и формирует ответы;
* Обработка данных с использованием ИИ - выполняет NLU-анализ и обогащение запроса;
* Сервис онтологии - предоставляет доступ к онтологической модели и ограничениям;
* Хранилище онтологии - графовая база данных для хранения концептов и связей.

## Диаграмма компонентов контейнера Сервер приложений (Backend API)

Диаграмма компонентов детализирует внутреннюю структуру контейнера Сервер приложений (Backend API), который является центральным оркестратором обработки запросов.

### Основные компоненты

* Контроллер ИИ API - Принимает запросы от веб-клиента по HTTPS/REST, выполняет первичную валидацию и передаёт запрос в сервис обработки;
* Сервис обработки запроса - управляет последовательностью шагов, обращается к внешним сервисам (ИИ и онтология), собирает итоговый результат;
* Клиент сервиса ИИ - инкапсулирует сетевое взаимодействие с контейнером Обработка данных с использованием ИИ по REST/JSON;
* Формирователь ответа - преобразует внутреннюю структуру результата (обогащённый запрос, уточнения, метаданные) в DTO/формат ответа для веб-клиента;
* Журналирование и аудит - фиксирует ключевые события обработки (получение запроса, вызовы сервисов, результат) для трассировки и анализа качества.

## Диаграмма компонентов контейнера Обработка данных с использованием ИИ

Диаграмма описывает внутреннюю структуру сервиса, который выполняет интеллектуальную обработку пользовательских запросов.

### Основные компоненты

* Контроллер ИИ API - принимает запрос на обогащение от сервера приложений по REST/JSON.
* Модуль NLU - анализирует текст запроса на естественном языке (сущности/термины/намерения).
* Модуль сопоставления с онтологией - связывает термины запроса с концептами онтологии.
* Клиент сервиса онтологии - обращается к сервису онтологии по REST/JSON для получения концептов/связей/ограничений.
* Движок обогащения - добавляет недостающие параметры и формирует уточнённую структуру запроса.
* Модуль оценки уверенности - оценивает полноту и качество результата обработки.
* Сборщик итоговой формулировки - формирует итоговую структурированную формулировку запроса для передачи специалисту.
